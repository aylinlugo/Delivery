# Delivery
Duarcion: 1 semana (5 días laborales)

## 1. Definir el objetivo del sprint   
- Semana 1: Desarrollar una aplicación móvil eficiente a los usuarios registrar pedidos de comida en restaurantes cercanos, realizar pagos seguros, optimizando la experiencia tanto para clientes como para repartidores y restaurantes.

## 2. Planificación (Día 1 - Mañana)  
- Reunión de Sprint Planning con todo el equipo (PO, SM, Dev Team).  
- Revisar backlog y seleccionar las historias de usuario relacionadas con el objetivo.  
- Definir tareas específicas para cada historia (programación, pruebas, diseño).  
- Asignar tareas y estimar tiempos.

## 3. Preparación (Día 1 - Tarde)  
- Refinar criterios de aceptación de cada historia.   
- Preparar ambiente de desarrollo (repositorios, ramas, herramientas).

## 4. Desarrollo (Días 2 a 4)  
- Programar funcionalidades asignadas.  
- Realizar pruebas unitarias básicas.  
- Hacer revisiones de código entre pares.  
- Actualizar progreso en la herramienta de gestión (Jira, Trello).

## 5. Testing y corrección (Día 5 - Mañana)  
- Ejecutar pruebas funcionales completas (QA, integración).  
- Corregir bugs o errores encontrados.  
- Validar que las historias cumplen criterios de aceptación.

## 6. Revisión y retrospectiva (Día 5 - Tarde)  
- Demo de lo desarrollado para el equipo y stakeholders.  
- Recolectar feedback y documentar mejoras para próximos sprints.  
- Retrospectiva: identificar qué funcionó y qué mejorar (procesos, comunicación, herramientas).

## 7. Comunicación diaria  
- Realizar daily stand-ups de 10-15 minutos cada mañana para sincronizar avances, identificar bloqueos y planificar el día.
