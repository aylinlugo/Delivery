# Delivery
Duarcion: 1 semana (5 días laborales)
## Descripcion del proyecto:
Desarrollar una aplicación móvil eficiente a los usuarios registrar pedidos de comida en restaurantes cercanos, realizar pagos seguros, optimizando la experiencia tanto para clientes como para repartidores y restaurantes.

Objetivo del Sprint 1:

Implementar la funcionalidad básica de registro e inicio de sesión de usuarios y una vista preliminar de restaurantes cercanos, además de preparar el entorno y la infraestructura técnica para el desarrollo ágil de futuros sprints.

##Día 1 – Mañana: Sprint Planning
Actividad: Reunión con PO, SM y equipo Dev.

Tareas:
Revisar backlog y seleccionar historias para este sprint:
Historia 1: Como usuario, quiero registrarme con correo y contraseña.
Historia 2: Como usuario, quiero iniciar sesión para usar la app.
Historia 3: Como usuario, quiero ver una lista básica de restaurantes cercanos (datos simulados).
Desglosar historias en tareas técnicas:
Diseño UI para registro/login.
Desarrollo backend para manejo de usuarios (API REST básica).
Desarrollo frontend para registro e inicio.
Crear mock data para restaurantes.
Configuración inicial del proyecto en repositorio.
Estimación de tiempos (Planning Poker o similar).
Asignación de tareas.

Herramientas:
Jira o Trello (gestión de tareas).
Zoom / Teams / Meet para la reunión.
Slack o Discord para comunicación diaria.

##Día 1 – Tarde: Preparación técnica
Actividad: Configuración del entorno de desarrollo.
Tareas:
Crear repositorio en GitHub/GitLab.
Establecer ramas principales (main, develop, feature/registro).
Configurar entorno local y herramientas (IDE: Visual Studio Code).
Preparar simuladores/emuladores móviles (Android Studio o Xcode).
Definir estándares de código y flujo de trabajo Git (pull requests, revisiones).
Refinar criterios de aceptación para cada historia.

Herramientas:
GitHub/GitLab para control de versiones.
Visual Studio Code.
Android Studio / Xcode (para emuladores).
Slack para comunicación rápida.

##Días 2 a 4: Desarrollo
Actividad: Codificación y pruebas unitarias.
Tareas:
Desarrollar la pantalla de registro e inicio de sesión (frontend móvil con React Native o Flutter).
Programar la API REST básica para registro e inicio (Node.js con Express o Django REST Framework).
Crear mock data para restaurantes y mostrar listado básico en app.
Escribir pruebas unitarias para backend y frontend.
Revisiones de código diarias entre pares (code review).
Actualizar Jira/Trello con avances y bloqueos.

Herramientas:
React Native o Flutter (desarrollo móvil).
Node.js + Express o Django REST Framework (backend).
Jest, Mocha o similar para pruebas unitarias.
GitHub para pull requests y revisiones.
Jira o Trello para seguimiento.

##Día 5 – Mañana: Testing y corrección
Actividad: QA y corrección de errores.

Tareas:
Pruebas funcionales del registro, login y lista de restaurantes.
Validar criterios de aceptación.
Corregir bugs reportados por testers.
Asegurar que todo esté listo para demo.

Herramientas:
Postman para pruebas API.
Simuladores/emuladores para pruebas UI.
Jira para gestión de bugs.

##Día 5 – Tarde: Demo y Retrospectiva
Actividad: Presentación y análisis del sprint.

Tareas:
Demo al PO y stakeholders:
Mostrar funcionalidad de registro, login y lista de restaurantes simulados.
Recoger feedback para mejoras.
Retrospectiva con el equipo:
Qué funcionó bien (ejemplo: comunicación diaria eficiente).
Qué mejorar (ejemplo: planificación más detallada).
Documentar acciones para siguiente sprint.

Herramientas:
Zoom/Teams para la demo y reunión.
Jira/Trello para documentar feedback y tareas pendientes.
Comunicación diaria:
Daily stand-up de 10-15 minutos cada mañana.
Compartir avances, impedimentos y planes para el día.
Herramienta: Slack o Discord.
